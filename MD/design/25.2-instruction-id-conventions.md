# Spec instruction ID 慣例

> **狀態**：自 2026-05-10（Sprint 25.2）生效
> **這份文件存在的原因**：spec inheritance（doc 23 + 25）需要每個 instruction
> 都有 stable、global unique 的字串 ID，這樣 child CPU spec 才能用 reference
> override / remove parent instruction。本文件釘住 ID 格式，讓 25.2 的
> auto-retrofit + 未來手寫 spec 保持一致。

## 格式

```
<MNEMONIC>_<operand_shape>[_sel<value>]
```

- **MNEMONIC** — 大寫、與 spec 的 `mnemonic` field 完全一致
  （`ADD`、`MOV`、`IMUL`、`LOOPE`、`INSB` ...）。
- **operand_shape** — 從 format `name` 衍生的小寫 snake_case、去掉前面的
  mnemonic prefix：
  - format `AddRm8R8` → `rm8_r8`
  - format `MovAlMoffs8` → `al_moffs8`
  - format `OrAxImm16` → `ax_imm16`
- **sel\<value\>** — 只有 format hosts 多個 instruction 透過 `selector` field
  區分（group-byte ALU / shift / FE-FF）時才用。`<value>` 是 selector 的 raw
  value、去掉 `0b`/`0x` prefix。

## Operand-shape 詞彙

| Token | 意思 | 範例 |
|---|---|---|
| `rm8` / `rm16` | r/m8 或 r/m16（ModR/M-driven；reg 或 mem） | `ADD_rm8_r8` |
| `r8` / `r16` | encoded register（從 ModR/M reg field） | `ADD_r8_rm8` |
| `al` / `ax` / `cl` / `dx` ... | 硬寫死的 register operand | `ADD_al_imm8`、`IN_al_dx` |
| `imm8` / `imm16` | 後接的 immediate byte/word | `ADD_ax_imm16` |
| `moffs8` / `moffs16` | direct memory offset（無 ModR/M） | `MOV_al_moffs8` |
| `rel8` / `rel16` | 相對 branch displacement | `JMP_rel8`、`CALL_rel16` |
| `sreg` | segment register（CS/DS/ES/SS） | `MOV_rm16_sreg` |
| `noargs` | 無 operand | `NOP_noargs`、`HLT_noargs` |
| `ptr1632` | far pointer (seg:off) | `JMP_ptr1632` |

## 範例（Sprint 25.2 retrofit 的真實 entry）

```
ADD_rm8_r8         (0x00)
ADD_rm16_r16       (0x01)
ADD_r8_rm8         (0x02)
ADD_al_imm8        (0x04)
ADD_ax_imm16       (0x05)

OR_rm8_r8          (0x08)
OR_al_imm8         (0x0C)

MOV_rm8_r8         (0x88)
MOV_al_moffs8      (0xA0)
MOV_rm16_sreg      (0x8C)

PUSH_AX            (0x50，單 register 專用 opcode)
PUSH_SP            (0x54)   # sprint 25.3 會對 i80186 override 這個
POP_AX             (0x58)

JMP_rel8           (0xEB)
JMP_rel16          (0xE9)
JMP_ptr1632        (0xEA)
LOOP_rel8          (0xE2)

INT_3              (0xCC)   # 硬寫死的 int 3
INT_imm8           (0xCD)
IRET_noargs        (0xCF)
```

## Group-byte instruction（selector path）

F6/F7/FE/FF/D0-D3/80-83 等 group byte，format hosts 多達 8 個 instruction，
透過 ModR/M reg 區分。ID 加 `_sel<bits>` suffix：

```
ADD_rm8_imm8_sel000      # 80 /0
OR_rm8_imm8_sel001       # 80 /1
ADC_rm8_imm8_sel010      # 80 /2
...
NEG_rm8_sel011           # F6 /3
NOT_rm8_sel010           # F6 /2
MUL_rm8_sel100           # F6 /4
IMUL_rm8_sel101          # F6 /5
DIV_rm8_sel110           # F6 /6
IDIV_rm8_sel111          # F6 /7
```

## 驗證規則（SpecLoader / SpecValidator 強制執行）

1. **格式**：必須 match `^[A-Z][A-Z0-9_]*$` — 只能大寫 / 數字 / 底線。
   不能有空格、不能小寫 mnemonic 混搭。
2. **唯一性**：單個 instruction-set spec 的每個 ID（如果有 inheritance、
   要 post-merge 之後）都必須 global unique。Loader 在 collision 時會 throw。
3. **Inheritance 必要**：child spec 想 override / remove 的 instruction 都必須有 ID。
   Sprint 25.1+25.2 過渡期暫時 optional；sprint 25.3 之後 ID 是唯一的
   override anchor。
4. **穩定性**：一旦 ID ship 在某個 spec 而且被 child override 引用，
   就**不要改名**。如果 encoding 真的變了，加新的 instruction 帶新 ID、
   把舊的 remove。

## ID 產生工具

`tools/spec_id_audit.py` 自動從既有 format name 產生 ID。它是 idempotent
（重跑帶 `--apply` 會重寫同樣的 ID）、collision 存在時拒絕 apply。i8086
retrofit 用過它；未來 CPU（i80186 以後）一開始就手寫 ID。
