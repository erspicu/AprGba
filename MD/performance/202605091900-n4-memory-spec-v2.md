# N4 closeout — memory spec v2 + perf bench

> **Status (2026-05-09)**：N4.0–N4.5 完工後量化。N4 把 NesMemoryBus 從
> N3.2 的「region-table linear scan + side_effects[0] 隱式 routing」推到
> 「page-table O(1) dispatch + offset semantics + 顯式 handler key」。
>
> 主要結果：legacy backend 從 N3.4 的 **1.57 MIPS** 回升到 **1.65 MIPS**
> （recover ~5pp 之 7pp regression），距 N1 baseline 的 1.69 MIPS 只差
> ~2%。Declarative ratio 從 N3 的 70% 推到約 **78%**。

---

## 1. Bench 結果（3 runs sequential，5-min cap）

ROM: `test-roms/blargg_nes_cpu_test5/cpu.nes`
Workload: `--run --max-cycles=110000000` (~62 emulator-seconds)
Build: Debug (`dotnet build AprGba.slnx --no-incremental`)
Commit: `abad579` (N4.5 末)

| Backend | Run 1 | Run 2 | Run 3 | **Avg** | **MIPS** | vs N3.4 | vs N1 baseline |
|---|---:|---:|---:|---:|---:|---:|---:|
| legacy           | 21.522s | 21.560s | 21.686s | **21.59s** | **1.65** | 1.57 → 1.65 (**+5%**) | 1.69 → 1.65 (-2%) |
| json per-instr   | 42.961s | 43.315s | 43.363s | **43.21s** | **0.82** | 0.81 → 0.82 (+1%, noise) | 0.83 → 0.82 (-1%) |
| json-block       | 35.483s | 36.089s | 35.502s | **35.69s** | **0.80** | 0.80 → 0.80 (=) | 0.78 → 0.80 (+3%) |

### 1.1 Legacy 回升分析

N3.2 把 hardcoded `if-else` chain 換成 4-region linear scan，crossover
penalty ≈ 7%（N3.4 量化）。N4.3 page-table O(1) dispatch 把 hot path
從「~2.5 iter linear scan + bound check」壓到「1 array index +
1 enum switch」— 每次 CPU bus access 省 ~3 conditional branches。

剩 ~2% 距 N1 baseline 是因為 N4 仍透過 `RegionKind` enum + switch
dispatch（vs N1 直接 inlined hardcoded path）。要再壓需要走 doc #22
§3.2 描述的 delegate-based dispatch（實際發 indirect call），但現在
測 perf 還沒值得 — 5% 回升已是 N4 主目標。

### 1.2 JIT backend 一致性

per-instr / block-JIT 都在 noise 範圍內。Memory spec 重整對 JIT
hot path 影響可忽略 — JIT 走自己的 LLVM IR、僅 cold path 才呼叫
ReadByte/WriteByte。

### 1.3 結果一致性

三 backend 都到 PC=$8003 self-loop（all 11 subtest PASS）；blargg
cpu_test5 PPU nametable 顯示 "All tests complete"（N4.4 PPU offset
semantics 不破 register handler）。

## 2. Declarative ratio 量化（N3 → N4）

| Layer | N3 後 | N4 後 | Δ | 備註 |
|---|---|---|---|---|
| CPU register file | 100% | 100% | – | unchanged |
| Instruction encoding (decoder) | 100% | 100% | – | unchanged |
| Instruction semantics | 95% | 95% | – | unchanged |
| Cycle multiplier | 100% | 100% | – | unchanged |
| Block-JIT cycle accounting | 90% | 90% | – | unchanged |
| **Memory bus dispatch** | 80% | **95%** | **+15%** | N4.3 page-table + N4.4 offset semantics + N4.5 explicit handler |
| **Region routing** | 70% | **95%** | **+25%** | N4.2 explicit handler key (vs N3 的 side_effects[0] magic) |
| Interrupt routing | 90% | 90% | – | unchanged |
| Per-instr cycle table | 60% | 60% | – | N3.3 spec format limitation 仍未解 |
| Mapper logic | 0% | 0% | – | escape hatch — by design |
| PPU/APU register handlers | 0% | 0% | – | escape hatch — by design |
| Access widths / wait states | 0% | **100%** (declared) | **+100%** | N4.5 spec 已宣告，runtime 強制留 future |

**加權平均**：N3 ~70% → N4 **~78%**（推進 8pp；剩 22% 是 fundamental
escape hatches + N3.3 cycle blocker）。

### 2.1 N4 的關鍵突破

1. **Mirror semantics 從脆弱絕對 addr 改成 offset-local**（N4.4） —
   PPU register handler 完全不知道自己住在 `0x2000`；spec 改
   addr_start 即可重新定位，不需動 handler code。
2. **Explicit handler key 取代 side_effects[0] magic**（N4.2） —
   spec readability 大增；schema 自我描述能力提升。
3. **O(1) page-table dispatch**（N4.3） — perf 救回；同時 page table
   為未來 fastmem `TryGetHostPointer` query API 鋪好結構。
4. **Schema 為其他 CPU 鋪路**（N4.5） — GBA + GB DMG specs 升 v2 已
   含 allowed_widths / wait_states / readable+writable，runtime 還沒
   強制但 spec 已 documentation-ready。

### 2.2 Spec example diff (N3 → N4)

```diff
 {
+    "spec_version": "2.0",
     "name": "nes-ntsc",
     "cpu": "Ricoh2A03",
+    "unmapped_behavior": "zero",
     "memory_regions": [
         {
             "name": "ppu_io",
             "addr_start": "0x2000",
             "addr_end_exclusive": "0x4000",
             "type": "io",
-            "side_effects": ["ppu"],
-            "mirror_mask": "0x2007"
+            "handler": "ppu",
+            "mirror_mask": "0x0007",
+            "allowed_widths": [8],
+            "volatile": true
         }
     ]
 }
```

`mirror_mask` 從 `"0x2007"` 收成 `"0x0007"`（純 low-bit 遮罩）— 因為
N4.4 套 offset 不套絕對 addr，mirror_mask 不再混 region start bits。

## 3. 未實作項目（N4 範圍外）

per design doc #22 §4：

- **ARM 32-bit 2-level page table** — N4 只做 NES（NES 16-bit / 32-byte
  page → 2048 entries × 8B = 16KB ok）。GBA 32-bit 走 hardcoded path 留
  在 GbaMemoryBus；N5 / 後續決定是否升級。
- **wait_states runtime 強制** — schema 已宣告，runtime 還沒 read。
  GBA cart timing 邏輯仍 hardcoded。
- **fastmem `TryGetHostPointer` query API** — page table 結構已 ready；
  block-JIT 端 GEP-store 整合留 future。
- **`allowed_widths` enforcement** — schema declared，bus 還沒拒絕
  out-of-spec width 的 access。NES 沒影響（全 8-bit）；GBA 升級時用得到。
