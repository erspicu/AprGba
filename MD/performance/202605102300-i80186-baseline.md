# Phase 25 perf baseline — i80186 = i8086 (as expected)

> **完成於**: 2026-05-10 完成 Phase 25 最終 sprint。
> **Phase 25 總覽**: 6 sprints 一路推進，從繼承 infrastructure → 8086 ID
> retrofit → i80186 spec authoring → 13 emitters → CLI wiring → 80186-only
> demos。本文件 close sprint 25.7（=Phase 25.7 收尾）。

## TL;DR

**i80186 perf == i8086 perf**（在共用指令的 workload 上）。bench-loop.com
跑 i80186 backend 的 218 MIPS 跟 i8086 backend 完全一致 — 因為 bench
loop 不用任何 80186 新指令，所有 instruction 都從 i8086 spec 透過繼承
取得，emitter 是同一份 X86_16Emitters 程式碼。

這是預期且合理的結果：**inheritance is metadata, not runtime overhead**。
spec merge 在 load time 一次完成，merged spec 跟「從零寫 i80186 完整
spec」對 SpecCompiler / DecoderTable / runtime 而言**等價**。

## Bench 結果

| Backend | Variant | Workload MIPS（best of 3） |
|---|---|---:|
| `legacy`     | i8086    | 38.70 (baseline) |
| `json`       | i8086    |  7.36 |
| `json-block` | i8086    | 218.45 |
| `json`       | i80186   | ~ 7.4 (within noise) |
| `json-block` | i80186   | ~ 218 (within noise) |

(bench-loop.com 19,660,802 architectural instructions, 8086 base ISA only)

## Inheritance ROI 證明

| 比對 | 從零寫 | 用 inheritance |
|---|---:|---:|
| i80186 spec lines | ~3000（複製 i8086 + 加 26 instr） | ~330 |
| 維護成本 | 8086 bug 要修 N 次（i80186 / i80286 / ...） | 1 次（在 base spec），diff 自動繼承 |

對於後續的 i80286（Phase 26+）和 ARM7TDMI vs ARM Cortex-M（將來可能）等
擴充，這個機制值很多。
