# Phase 26 — Intel 80286 real-mode v1 (minimum viable)

> **Closed**: 2026-05-10/11
> **Scope claim**: framework + first observable 80286 instruction shipped.
> Full 80286 ISA (LGDT/LIDT/SGDT/SIDT/LMSW write/SLDT/STR/LLDT/LTR/LAR/LSL/
> VERR/VERW + protected-mode segmentation/privilege/TSS) is Phase 27+
> multi-week work, intentionally deferred.

## Inheritance chain proven at depth 3

```
i8086    (depth 0, 149 instructions)
  └ i80186  (depth 1, 149 + 26 = 175 instructions; +1 silicon-quirk override)
      └ i80286  (depth 2, 175 + 1 set "TwoByteEsc" with CLTS + SMSW)
```

The depth-cap=4 invariant shipped in Sprint 25.1 is now load-tested at
real depth 3. Phase 27 (which extends i80286 with protected mode) would
be depth 4 — the inheritance machinery's hard cap.

## Verified end-to-end demos

```powershell
# CLTS (0F 06): no-op stub but proves 0F prefix decoder works
apr-x86 --rom=test-roms/x86/26-clts.com --backend=json-block --variant=i80286
  → IP advances 0x100 → 0x104 (NOP + 0F 06 + HLT all consumed)
  → halted: True

# SMSW AX (0F 01 E0): observable side-effect
apr-x86 --rom=test-roms/x86/26-smsw.com --backend=json-block --variant=i80286
  → AX = 0xFFF0   (real-mode reset MSW per Intel 80286 PRM)
  → IP = 0x105
  → halted: True
```

## Framework changes (the real Phase 26 deliverable)

The instruction count is small but the **framework gained these new
mechanisms**:

| Mechanism | Why it matters |
|---|---|
| `instruction_sets_added` in `instruction_set_diff` | Child specs can add NEW instruction sets, not just modify parent's. Required for any prefix-driven secondary opcode tables (0F escape, future REX prefix for x86-64, etc.). |
| 0F prefix recognized in X86 length oracle | BlockDetector no longer mis-truncates blocks containing 80286 system instructions. |
| BlockDetector busLengthOracle path consults `prefixSubDecoders` | Two-byte-opcode dispatch via separate decoder table. Mirrors LR35902 CB-prefix mechanism. |
| BlockDetector `busOpcodeStartedAt` tracking | When a prefix sub-decoder fires, opcode spans 2 bytes; PackedTailBytes packing must skip past both. Critical for FetchImm8/16 to read the right bytes inside emitter IR. |
| 80286 dispatch group emitter pattern | Runtime ModR/M-reg dispatch (matches F6/F7 group in 8086). Phase 27 builds the full LMSW/LGDT/etc. on this scaffold. |

## Phase 27 deferred work

What's NOT shipped (intentionally), grouped by the work it would entail:

**Real-mode-completion (would be Phase 26.x or fresh Phase 27a):**
- LMSW write path: needs MSW state register added to layout + emitter wiring
- SMSW reads real MSW (not constant 0xFFF0)
- LGDT/LIDT/SGDT/SIDT: load/store 6-byte (16-bit limit + 24-bit base) — needs
  GDTR_BASE / GDTR_LIMIT / IDTR_BASE / IDTR_LIMIT state slots
- LLDT/SLDT/LTR/STR: 16-bit register r/w — needs LDTR / TR slots
- LAR/LSL/VERR/VERW: real-mode no-op stubs are correct; protected-mode
  semantics are different and arrive in Phase 27b
- CLTS: clear MSW.TS — no-op until MSW exists

**Protected mode (Phase 27 proper, multi-week):**
- Descriptor table format parsing (8-byte segment descriptors)
- Privilege levels (CPL/RPL/DPL) and ring transitions
- Segmentation rewrite (selector → descriptor table → base/limit lookup)
- New exception model (#GP, #SS, #NP, #TS, #UD with error codes)
- Task switching via TSS
- Protected-mode entry (LMSW with PE bit set)
- LOADALL undocumented instruction (escape from protected mode)

Estimated scope: 5-8 sprints, ~3-4 work weeks.

## Why we stopped at Phase 26 v1

Phase 26 v1's deliverable is "the FRAMEWORK supports adding 80286 — chain
depth 3 works, 0F prefix decodes, system instruction emitter pattern is
established, one observable instruction proven." That validates the
inheritance machinery's design under realistic load.

Filling in the rest of 80286 (real-mode-completion + protected mode)
is mostly mechanical work — same patterns repeated. Doing it inside one
session/loop runs out of context budget before it's shippable; better
to pause at a clean checkpoint, recover context, and continue Phase 27
fresh when there's slack.

The roadmap calls this out explicitly: doc 24 §24.8 had two halves
("real-mode + protected-mode"), and we've now shipped a real-mode
minimum-viable subset that proves the framework. The remaining 80286
work is Phase 27.
