> **收尾**：2026-05-10/11
> **Scope 宣告**：framework + 第一個可觀察 80286 指令出貨。
> 完整 80286 ISA（LGDT/LIDT/SGDT/SIDT/LMSW write/SLDT/STR/LLDT/LTR/LAR/LSL/
> VERR/VERW + 保護模式 segmentation/privilege/TSS）是 Phase 27+ 的多週工作、

## Inheritance chain 在 depth 3 驗證過

```
i8086    (depth 0, 149 instructions)
  └ i80186  (depth 1, 149 + 26 = 175 instructions；+1 silicon-quirk override)
      └ i80286  (depth 2, 175 + 1 set "TwoByteEsc" with CLTS + SMSW)
```

Sprint 25.1 出的 depth-cap=4 invariant 現在 load-test 到實際 depth 3 了。
Phase 27（i80286 加保護模式）會是 depth 4 — inheritance machinery 的 hard cap。

## 驗證過的端到端 demo

```powershell
# CLTS (0F 06)：no-op stub 但證明 0F prefix decoder 有 work
apr-x86 --rom=test-roms/x86/26-clts.com --backend=json-block --variant=i80286
  → IP 推進 0x100 → 0x104（NOP + 0F 06 + HLT 都吃掉）
  → halted: True

# SMSW AX (0F 01 E0)：有可觀察 side-effect
apr-x86 --rom=test-roms/x86/26-smsw.com --backend=json-block --variant=i80286
  → AX = 0xFFF0   (real-mode reset MSW per Intel 80286 PRM)
  → IP = 0x105
  → halted: True
```

## Framework 改動（Phase 26 真正的 deliverable）

Instruction 數量小但 **framework 多了以下 mechanism**：

| Mechanism | 為何重要 |
|---|---|
| `instruction_set_diff` 裡的 `instruction_sets_added` | Child spec 可以加 NEW instruction set、不只是改 parent 的。任何 prefix-driven secondary opcode table（0F escape、未來 x86-64 的 REX prefix 等）都需要。 |
| X86 length oracle 認得 0F prefix | BlockDetector 不再把含 80286 system 指令的 block 錯誤截斷。 |
| BlockDetector busLengthOracle path 諮詢 `prefixSubDecoders` | Two-byte-opcode dispatch 透過獨立 decoder table。Mirror LR35902 的 CB-prefix 機制。 |
| BlockDetector `busOpcodeStartedAt` 追蹤 | 當 prefix sub-decoder fire 時，opcode 跨 2 byte；PackedTailBytes packing 必須跳過兩個 byte。FetchImm8/16 在 emitter IR 內讀對 byte 的關鍵。 |
| 80286 dispatch group emitter 樣式 | Runtime ModR/M-reg dispatch（match 8086 的 F6/F7 group）。Phase 27 在這個 scaffold 上建完整的 LMSW/LGDT/etc.。 |

## Phase 27 延後的工作

刻意 NOT 出貨的、依需要做的工作分組：

**Real-mode-completion（會是 Phase 26.x 或新 Phase 27a）：**
- LMSW write path：需要 layout 加 MSW state register + emitter wiring
- SMSW 讀真正的 MSW（不是 constant 0xFFF0）
- LGDT/LIDT/SGDT/SIDT：load/store 6-byte（16-bit limit + 24-bit base）—
  需要 GDTR_BASE / GDTR_LIMIT / IDTR_BASE / IDTR_LIMIT state slot
- LLDT/SLDT/LTR/STR：16-bit register r/w — 需要 LDTR / TR slot
- LAR/LSL/VERR/VERW：real-mode no-op stub 是對的；protected-mode semantics
  不同、Phase 27b 才會做
- CLTS：清 MSW.TS — MSW 不存在前是 no-op

**保護模式（正式 Phase 27、多週）：**
- Descriptor table 格式解析（8-byte segment descriptor）
- Privilege level（CPL/RPL/DPL）與 ring transition
- Segmentation 重寫（selector → descriptor table → base/limit lookup）
- 新 exception model（#GP、#SS、#NP、#TS、#UD 帶 error code）
- 透過 TSS 做 task switching
- Protected-mode entry（LMSW 帶 PE bit）
- LOADALL 未文件化指令（從 protected mode 逃出）

估計 scope：5-8 sprint、~3-4 工作週。

## 為何在 Phase 26 v1 停下

Phase 26 v1 的 deliverable 是「FRAMEWORK 支援加 80286 — chain depth 3
work、0F prefix decode、system instruction emitter pattern 確立、
一個可觀察 instruction 驗證過」。這在 realistic load 下驗證了
inheritance machinery 的設計。

剩下的 80286（real-mode-completion + 保護模式）填空大致是機械化工作 —
同樣 pattern 重複。在一個 session/loop 裡做完會在出貨之前 run out of
context budget；比較好的做法是在乾淨的 checkpoint 停下、recover context、
有 slack 時再開 Phase 27。

Roadmap 明確 call out 這點：doc 24 §24.8 有兩個半段（"real-mode +
protected-mode"），現在出了 real-mode minimum-viable subset 證明 framework。
剩下的 80286 工作是 Phase 27。
