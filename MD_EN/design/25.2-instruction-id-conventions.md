# Spec instruction ID conventions

> **Status**: in-effect 2026-05-10 (Sprint 25.2)
> **Why this doc**: spec inheritance (doc 23 + 25) needs every instruction
> to have a stable, globally unique string ID so child CPU specs can
> override / remove parent instructions by reference. This doc nails
> down the ID format so 25.2's auto-retrofit + future hand-authored specs
> stay coherent.

## Format

```
<MNEMONIC>_<operand_shape>[_sel<value>]
```

- **MNEMONIC** — uppercase, exactly the spec's `mnemonic` field
  (`ADD`, `MOV`, `IMUL`, `LOOPE`, `INSB`, ...).
- **operand_shape** — lowercase snake_case derived from the format
  `name` field, with the leading mnemonic prefix stripped:
  - format `AddRm8R8` → `rm8_r8`
  - format `MovAlMoffs8` → `al_moffs8`
  - format `OrAxImm16` → `ax_imm16`
- **sel\<value\>** — only when the format hosts multiple instructions
  distinguished by a `selector` field (group-byte ALU / shift / FE-FF).
  `<value>` is the selector's raw value with `0b`/`0x` prefixes stripped.

## Operand-shape vocabulary

| Token | Meaning | Example |
|---|---|---|
| `rm8` / `rm16` | r/m8 or r/m16 (ModR/M-driven; reg or mem) | `ADD_rm8_r8` |
| `r8` / `r16` | encoded register from ModR/M reg field | `ADD_r8_rm8` |
| `al` / `ax` / `cl` / `dx` ... | hardcoded register operand | `ADD_al_imm8`, `IN_al_dx` |
| `imm8` / `imm16` | trailing immediate byte/word | `ADD_ax_imm16` |
| `moffs8` / `moffs16` | direct memory offset (no ModR/M) | `MOV_al_moffs8` |
| `rel8` / `rel16` | relative branch displacement | `JMP_rel8`, `CALL_rel16` |
| `sreg` | segment register (CS/DS/ES/SS) | `MOV_rm16_sreg` |
| `noargs` | no operand | `NOP_noargs`, `HLT_noargs` |
| `ptr1632` | far pointer (seg:off) | `JMP_ptr1632` |

## Group-byte instructions (selector path)

For F6/F7/FE/FF/D0-D3/80-83 group bytes the format hosts up to 8
instructions distinguished by ModR/M reg. ID gets `_sel<bits>` suffix:

```
ADD_rm8_imm8_sel000      # 80 /0
OR_rm8_imm8_sel001       # 80 /1
ADC_rm8_imm8_sel010      # 80 /2
...
NEG_rm8_sel011           # F6 /3
NOT_rm8_sel010           # F6 /2
MUL_rm8_sel100           # F6 /4
IMUL_rm8_sel101          # F6 /5
DIV_rm8_sel110           # F6 /6
IDIV_rm8_sel111          # F6 /7
```

## Validation rules (enforced by SpecLoader / SpecValidator)

1. **Format**: must match `^[A-Z][A-Z0-9_]*$` — uppercase / digit /
   underscore only. No spaces, no lowercase mnemonic mix-ups.
2. **Uniqueness**: every ID in a single instruction-set spec (post-merge
   if there's inheritance) must be globally unique. Loader throws on
   collision.
3. **Required for inheritance**: any instruction that a child spec wants
   to override / remove must have an ID. Currently optional during
   sprint 25.1+25.2 transition; sprint 25.3 onwards uses IDs as the
   only override anchor.
4. **Stability**: once an ID ships in a spec that's referenced by a
   child override, do NOT rename it. Add a new instruction with a new
   ID and remove the old one if the encoding really changed.

## ID generation tooling

`tools/spec_id_audit.py` automates ID generation from existing format
names. It's idempotent (re-running with `--apply` rewrites the same IDs)
and refuses to apply when collisions exist. Used for the i8086
retrofit; future CPUs (i80186 onwards) hand-author IDs from the start.
