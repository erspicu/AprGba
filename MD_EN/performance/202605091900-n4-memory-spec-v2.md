# N4 closeout — memory spec v2 + perf bench

> **Status (2026-05-09)**: Quantification after N4.0–N4.5. N4 pushed
> NesMemoryBus from N3.2's "region-table linear scan + side_effects[0]
> implicit routing" to "page-table O(1) dispatch + offset semantics +
> explicit handler key".
>
> Main result: the legacy backend recovered from N3.4's **1.57 MIPS**
> back to **1.65 MIPS** (recovered ~5pp out of the 7pp regression),
> only ~2% off the N1 baseline of 1.69 MIPS. Declarative ratio went
> from N3's 70% to about **78%**.

### 1.1 Legacy bounce-back analysis

N3.2 changed the hardcoded `if-else` chain to a 4-region linear scan,
crossover penalty ≈ 7% (quantified at N3.4). N4.3's page-table O(1)
dispatch compresses the hot path from "~2.5 iterations of linear scan
+ bound check" down to "1 array index + 1 enum switch" — saving ~3
conditional branches per CPU bus access.

The remaining ~2% gap to the N1 baseline is because N4 still goes
through `RegionKind` enum + switch dispatch (vs N1's direct inlined
hardcoded path). To squeeze it further would require taking the
delegate-based dispatch path described in doc #22 §3.2 (an actual
indirect call), but right now perf does not justify it — the 5%
recovery is already N4's primary goal.

### 1.2 JIT backend consistency

Both per-instr and block-JIT are within noise. The memory spec rework
has negligible impact on JIT hot paths — JIT goes through its own LLVM
IR and only the cold paths call ReadByte/WriteByte.

### 1.3 Result consistency

All three backends reach the PC=$8003 self-loop (all 11 subtests PASS);
blargg cpu_test5 PPU nametable shows "All tests complete" (N4.4's PPU
offset semantics did not break the register handler).

## 2. Declarative ratio quantification (N3 → N4)

| Layer | After N3 | After N4 | Δ | Notes |
|---|---|---|---|---|
| CPU register file | 100% | 100% | – | unchanged |
| Instruction encoding (decoder) | 100% | 100% | – | unchanged |
| Instruction semantics | 95% | 95% | – | unchanged |
| Cycle multiplier | 100% | 100% | – | unchanged |
| Block-JIT cycle accounting | 90% | 90% | – | unchanged |
| **Memory bus dispatch** | 80% | **95%** | **+15%** | N4.3 page-table + N4.4 offset semantics + N4.5 explicit handler |
| **Region routing** | 70% | **95%** | **+25%** | N4.2 explicit handler key (vs N3's side_effects[0] magic) |
| Interrupt routing | 90% | 90% | – | unchanged |
| Per-instr cycle table | 60% | 60% | – | N3.3 spec format limitation still unresolved |
| Mapper logic | 0% | 0% | – | escape hatch — by design |
| PPU/APU register handlers | 0% | 0% | – | escape hatch — by design |
| Access widths / wait states | 0% | **100%** (declared) | **+100%** | N4.5 spec already declares it; runtime enforcement deferred |

**Weighted average**: N3 ~70% → N4 **~78%** (advanced 8pp; the
remaining 22% is fundamental escape hatches + the N3.3 cycle blocker).

### 2.1 Key N4 breakthroughs

1. **Mirror semantics changed from fragile absolute addr to
   offset-local** (N4.4) — the PPU register handler has no idea it
   lives at `0x2000`; changing addr_start in the spec is enough to
   relocate it without touching handler code.
2. **Explicit handler key replacing side_effects[0] magic** (N4.2) —
   spec readability greatly improved; the schema is more
   self-describing.
3. **O(1) page-table dispatch** (N4.3) — perf recovered; the page
   table also paves structural ground for the future fastmem
   `TryGetHostPointer` query API.
4. **Schema paves the way for other CPUs** (N4.5) — the GBA + GB DMG
   specs have been promoted to v2 with allowed_widths / wait_states /
   readable+writable; runtime does not yet enforce, but the spec is
   documentation-ready.

### 2.2 Spec example diff (N3 → N4)

```diff
 {
+    "spec_version": "2.0",
     "name": "nes-ntsc",
     "cpu": "Ricoh2A03",
+    "unmapped_behavior": "zero",
     "memory_regions": [
         {
             "name": "ppu_io",
             "addr_start": "0x2000",
             "addr_end_exclusive": "0x4000",
             "type": "io",
-            "side_effects": ["ppu"],
-            "mirror_mask": "0x2007"
+            "handler": "ppu",
+            "mirror_mask": "0x0007",
+            "allowed_widths": [8],
+            "volatile": true
         }
     ]
 }
```

`mirror_mask` shrinks from `"0x2007"` to `"0x0007"` (pure low-bit mask)
— because N4.4 applies the offset rather than the absolute addr,
mirror_mask no longer mixes in the region's start bits.

## 3. Items not implemented (out of N4 scope)

Per design doc #22 §4:

- **ARM 32-bit 2-level page table** — N4 only does NES (NES 16-bit /
  32-byte page → 2048 entries × 8B = 16KB ok). GBA 32-bit goes through
  the hardcoded path that stays in GbaMemoryBus; N5 / later decides
  whether to upgrade.
- **wait_states runtime enforcement** — schema declared, runtime does
  not read it yet. GBA cart timing logic still hardcoded.
- **fastmem `TryGetHostPointer` query API** — page-table structure is
  ready; integration with block-JIT GEP-store left for the future.
- **`allowed_widths` enforcement** — schema declared, but the bus has
  not yet rejected out-of-spec width accesses. Does not affect NES
  (all 8-bit); will matter when GBA is upgraded.
