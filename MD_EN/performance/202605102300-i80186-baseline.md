# Phase 25 perf baseline — i80186 = i8086 (as expected)

> **Closed**: 2026-05-10 — Phase 25 final sprint.
> **Phase 25 overview**: 6 sprints from inheritance infrastructure →
> 8086 ID retrofit → i80186 spec authoring → 13 emitters → CLI wiring
> → 80186-only demos. This note closes sprint 25.7 (= Phase 25.7
> closure).

## TL;DR

**i80186 perf == i8086 perf** (on shared-instruction workloads).
bench-loop.com on the i80186 backend hits the same 218 MIPS as on the
i8086 backend — because the bench loop uses no 80186-new instructions;
every instruction comes from the i8086 spec via inheritance, and the
emitters are the same `X86_16Emitters` code.

This is the expected and correct outcome: **inheritance is metadata,
not runtime overhead**. Spec merging happens once at load time, and
the merged spec is **equivalent** for SpecCompiler / DecoderTable /
runtime to "writing the full i80186 spec from scratch."

| Backend | Variant | Workload MIPS (best of 3) |

## Inheritance ROI evidence

| Metric | From scratch | Via inheritance |
|---|---:|---:|
| i80186 spec lines | ~3000 (copy i8086 + add 26 instr) | ~330 |
| Maintenance cost | An 8086 bug needs N fixes (i80186 / i80286 / ...) | 1 fix in the base spec, diff inherits automatically |

For follow-on work (i80286 in Phase 26+, future ARM7TDMI vs Cortex-M
extensions, etc.) the mechanism is well worth the up-front cost.
