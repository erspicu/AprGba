This is a beautifully scoped phase for your emulator. Implementing an FDC and DMA just enough to bootstrap a sector is a classic rite of passage in emulator development. 

Here are the precise answers and byte-by-byte guidelines to get your Phase 30 completed and booting successfully.

### Q1 — Minimum 8272 FDC Command Set
Your proposed list is almost perfect, but you are missing one crucial command that BIOSes use during media detection, and one pseudo-command.

**The Absolute Minimum Set:**
1.  **0x03 SPECIFY:** Sets up step rate, etc. No result phase, no IRQ.
2.  **0x07 RECALIBRATE:** Seeks to cylinder 0. No result phase, **generates IRQ 6**.
3.  **0x08 SENSE INTERRUPT STATUS:** Must be called after RECALIBRATE or SEEK to get ST0 and PCN (Present Cylinder Number). **Clears IRQ 6**.
4.  **0x0F SEEK:** Seeks to a specific cylinder. No result phase, **generates IRQ 6**.
5.  **0x06 READ DATA (usually 0x46, 0x66, or 0xE6 depending on MFM/MT/SK bits):** Reads sectors. Has a result phase, **generates IRQ 6** at the end.
6.  **0x0A READ ID (usually 0x4A with MFM bit):** **Yes, you need this.** Real BIOSes (especially XT/AT BIOSes trying to figure out if a drive is 360K, 1.2M, or 1.44M) will issue READ ID to read the CHS header of the first sector under the head to determine the current disk geometry and data rate.
7.  **Invalid Command (any unmapped opcode):** The BIOS often intentionally sends an invalid byte (like `0x00` or `0xFF`) to force the FDC into a known state. Return ST0 = `0x80` (Invalid Command).

*Note on 0x04 SENSE DRIVE STATUS:* Rarely needed just to boot DOS, but easy to implement (returns ST3). Safest to implement it.

### Q2 — Phase Boundaries & MSR (0x3F4) Polling
Your MSR bit dance is generally correct, but here is exactly what the BIOS expects when it reads `0x3F4`:

*   **RQM (Bit 7):** 1 = Ready for data transfer (read or write).
*   **DIO (Bit 6):** 0 = FDC expects host to WRITE (Command/Param). 1 = FDC expects host to READ (Result).
*   **NDM (Bit 5):** Execution mode. On PC/XT, always 0 (DMA mode).
*   **CB (Bit 4):** FDC Busy. Set to 1 when a command is in progress.
*   **D0B-D3B (Bits 0-3):** Drive busy bits. Set to 1 during a Seek/Recalibrate on that specific drive.

**The Gotcha:** The BIOS will execute a tight polling loop on the MSR before reading/writing the Data Register (`0x3F5`).
*   To write a command byte: BIOS waits for `(MSR & 0xC0) == 0x80` (RQM=1, DIO=0).
*   To read a result byte: BIOS waits for `(MSR & 0xC0) == 0xC0` (RQM=1, DIO=1).

If you change states *instantly* between CPU instructions, the emulator is perfectly fine, but make sure your MSR correctly reflects `RQM=1 | DIO=1` when you have bytes waiting in the result FIFO.

**Vital Missing Piece — The DOR (0x3F2):**
You didn't mention the Digital Output Register (`0x3F2`). You **must** implement this. The BIOS writes here to:
1.  Turn on the drive motor (Bit 4).
2.  Enable DMA/IRQ (Bit 3 = 1).
3.  **Reset the FDC** (Bit 2 = 0 resets, Bit 2 = 1 clears reset).
*When the BIOS pulses Bit 2 low then high, you must clear your FDC state machine and generate an IRQ 6.*

### Q3 — 8237 DMA Channel 2 Integration
**Correction on DMA ports:** 0x04 is Base Address, 0x05 is Word Count. They are 16-bit registers accessed via a single 8-bit port. The BIOS writes the Low byte, then the High byte. An internal flip-flop determines which byte is being written. The BIOS writes to `0x0C` (Clear Byte Pointer Flip-Flop) before writing to 0x04/0x05 to ensure it starts on the Low byte.

**Can you fake it with a synchronous burst transfer?**
**Yes! Absolutely.** For an MVP BIOS boot, cycle-accurate interleaved DMA is not required. When you receive the final byte of a `READ DATA` command:
1.  Read the current DMA Page (0x81), Base (0x04), Count (0x05).
2.  Calculate physical memory address: `(Page << 16) | Base`.
3.  Calculate length: `Count + 1` bytes (DMA count is N-1).
4.  Copy data directly from your `DiskImage` byte array to emulator RAM.
5.  **Crucial state update:** Update the DMA controller's state. Set Base Address to `Base + Length`, set Count to `0xFFFF` (Terminal Count reached), and set the Status Register (`0x08`) Bit 2 to indicate Channel 2 reached TC.
6.  Transition FDC to Result Phase and assert IRQ 6.

*This synchronous cheat is how 90% of emulators initially implement floppy support.*

### Q4 — IRQ 6 Wiring
*   **PIC Wiring:** Yes, IRQ 6 goes to PIC line 6. In real mode (base 0x08), this fires `INT 0x0E`.
*   **When does BIOS unmask?** The BIOS typically unmasks IRQ 6 in the PIC's Interrupt Mask Register (`0x21`) right after turning on the floppy motor via DOR and right before issuing the command.
*   **When to Assert:** Assert the IRQ line when:
    *   A SEEK completes.
    *   A RECALIBRATE completes.
    *   A READ/WRITE/FORMAT Execution phase completes (entering Result phase).
    *   The FDC comes out of software reset (DOR bit 2 goes 0 -> 1).
*   **When to De-assert:** Clear the IRQ line when the CPU reads the *first byte* of the Result Phase from `0x3F5`, or when the CPU executes `SENSE INTERRUPT STATUS` (if there is no result phase).

### Q5 — READ DATA Command Details
For a 1.44MB floppy reading Boot Sector (C=0, H=0, S=1):

**Command Bytes from BIOS:**
1.  `0xE6` (MT=1, MFM=1, SK=0, Opcode=06)
2.  `0x00` (Head 0, Drive 0)
3.  `0x00` (Cyl 0)
4.  `0x00` (Head 0)
5.  `0x01` (Sector 1)
6.  `0x02` (Sector Size: 2 = 512 bytes)
7.  `0x12` (EOT: 18 sectors per track for 1.44MB)
8.  `0x1B` (GPL: standard for 1.44M)
9.  `0xFF` (DTL: ignored because Sector Size != 0)

*(Note on XT BIOS: Ensure your `pcxtbios.bin` actually supports 1.44MB 80x2x18 disks! A stock 1983 IBM PC/XT ROM only knows 360K. If using a custom/later XT ROM, it's fine).*

**Result Bytes (Successful Boot Sector Read):**
1.  **ST0:** `0x00` (Bits 7-6=00 Normal Termination. Bit 2=Head(0). Bits 1-0=Drive(0)).
2.  **ST1:** `0x00` (No errors).
3.  **ST2:** `0x00` (No errors).
4.  **Cyl:** `0x00` (Usually returns the CHS of the *next* sector).
5.  **Head:** `0x00`
6.  **Sector:** `0x02` (Because we just read sector 1).
7.  **Size:** `0x02` (512 bytes).

### Q6 — Architectural Concerns (Obscure Commands)
**Safe to defer?** Yes. Defer `FORMAT TRACK`, `VERIFY DATA`, `READ DELETED`, and all `SCAN` commands. If the BIOS sends them, just return an ST0 with the "Invalid Command" bit set:
*   Transition to Result Phase.
*   Return 1 byte: `0x80` (ST0 where Bit 7=1: Invalid Command).
*   *Do not generate an IRQ for invalid commands.*

**READ ID (0x0A):** As stated in Q1, **do not defer this**. Implement it.
*   **Execution:** Does not move the disk head. Just fakes reading the sector ID under the head.
*   **Result (7 bytes):** ST0, ST1, ST2, C, H, S, Size.
*   **Faking it:** Just return ST0=0, ST1=0, ST2=0, and the C, H, S, and Size (2) of whatever you are currently "seeked" to. Sector can just be 1. 

### Summary Action Plan for Phase 30
1.  **Ports:** Implement `0x3F2` (DOR - just track reset/motor state), `0x3F4` (MSR - state machine read), `0x3F5` (Data - FIFO read/write).
2.  **DMA:** Implement ports `0x04`, `0x05`, `0x0C` (flip-flop), `0x0B` (mode), `0x0A` (mask), `0x81` (page).
3.  **Burst Logic:** Hook the execution of `READ DATA` to trigger your synchronous memory copy using DMA registers, update DMA count to `0xFFFF`, and fire IRQ 6.
4.  **Commands:** Handle `SPECIFY`, `RECALIBRATE`, `SENSE INT`, `SEEK`, `READ DATA`, `READ ID`. Everything else returns `0x80`.
